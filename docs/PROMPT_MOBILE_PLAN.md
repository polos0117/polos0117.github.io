# 통합 생성기(prompt.html) — 모바일 UI 수정안 (2026-10-29)

사용자: "트리 구조로 한 단계씩 고르는 건 좋은데, 모바일에선 불편하다 — 모바일에서도 쓰기 편한 UI 구성으로 수정안을".
이 문서는 **수정안**이다 — 코드는 아직 안 바꿨다. 아래 ①~⑧ 을 그대로 하면 되게 적었고, 어디를 먼저 할지도 적었다.
현재 화면은 390×844(휴대폰)에서 포켓몬 → 피카츄 → 일상컷으로 끝까지 가며 재 봤다(tests 와 같은 서버).
2절의 그림을 그대로 그린 정적 시안이 `docs/prompt-mobile-mock.html` 이다(가짜 자료 — `?m=step` 단계 화면, `?m=done` 다 고른 화면. 폰 폭으로 연다).

## 1. 지금 무엇이 불편한가 — 잰 것

| 자리 | 390×844 에서 | 왜 불편한가 |
|---|---|---|
| 머리(제목·설명 글) | 위 **≈300px** 가 제목·설명·여백 — 첫 화면의 1/3 | 매번 보는 글인데 단계마다 자리를 먹는다. 칩·판은 그 아래에서 시작 |
| 고른 단계 칩 | 일상컷 다 고르면 칩 **15개 · 9줄 ≈ 640px** | 칩이 줄바꿈으로 쌓여 판을 화면 밖으로 민다. 「다 골랐다」에서 지시문은 **1,300px 아래**(두 화면 뒤) |
| 선택지 목록 | 장소 단계 쪽 높이 **4,900px**(6화면), 해방 켜면 **7,400px** | 칸이 2열·설명 두 줄이라 길다. 묶음(집·거리·도시…)이 모두 세로로 쌓인다 |
| 단계의 단추 | 「해방」「이 칸 랜덤」「여기부터 다 랜덤」「다음」이 **목록 맨 아래** | 긴 목록은 끝까지 내려야 단추가 나온다. 엄지가 닿는 아래쪽에 늘 있는 단추가 없다 |
| 대상 목록 | 포켓몬 1,025명 → **36,000px** | 찾기 칸은 위에 붙어 있지만, 세대·가나다 같은 건너뛰기가 없다. 끝에서 고르면 위로 튄다 |
| 해방 | 체크박스 하나 + 트리 밖 목록이 **본 목록 아래에 따로** | 켜도 어디에 뭐가 생겼는지 안 보인다(목록 아래로 또 내려야) |
| 칩 글 | 「방향 over shoulder — 뒤돌아보기」처럼 길다 | 한 칩이 한 줄을 다 먹는다 |
| 결과 | 지시문 칸·「복사」가 쪽 맨 아래 | 고치고 복사하려면 매번 끝까지 내려간다 |
| 단계 바뀔 때 | 새 단계 윗머리가 화면 위에 있을 때만 올린다 | 긴 목록 중간에서 고르면 새 단계가 화면 밖에서 시작하는 때가 있다 |

PC(1280)는 괜찮다 — 칩이 한 줄, 선택지 4열, 단추가 바로 보인다. 그래서 **아래 안은 폭 ≤ 768px 에서만** 바뀌고 PC 는 그대로 둔다.

## 3. 바꿀 것 여덟 — 하나씩

> **진행**: ②③(칩 레일 한 줄 + 아래 막대)은 2026-10-29 적용했다(`prompt.html` CSS `@media (max-width: 768px)`, `prompt/hub.js` `hbarHTML`·`chipNext`·`mobile()`). 칩 글 한국어 머리만·다음 칸 ▸ 미리·단계 바뀌면 레일 아래로 올리기도 같이. 키보드는 초점이 아니라 `visualViewport` 높이로 본다(초점으로 숨기면 글 쓰다 바로 「다음」을 못 누른다). 같은 날 ④⑤ 도 적용(선택지 1열 줄·묶음 탭·해방을 같은 목록에, `optButtons(list, cur, tabKey)` · `st.tab`) — 장소 단계가 한 묶음 보기에서 ≈1,100px. 더해 사용자 요청으로 **「↺ 여기부터 다시」**(`restartFrom`): 지금 단계 뒤 칸을 다 비우고(해방·계획 표시도) 이 단계부터 다시 — 폰은 🎲 메뉴, PC 는 판 밑 단추. 카드 갈래는 새 카드(기본값)의 같은 단계 조각에서 값을 가져온다. 나머지 ①⑥⑦⑧ 은 아직.

### ① 위 레일 — 머리를 줄이고 경로를 한 줄로
- 제목 `h1` 은 한 줄(24px), 「ATELIER · 통합」 작은 글은 뺀다. 설명 글(`.lede`)은 「?」 단추로 접었다 펴는 `<details>` — 처음 한 번만 펼쳐져 있고(저장값 `hub.lede` 없을 때), 닫으면 기억.
- 그 아래 **경로 한 줄**: `포켓몬 › 피카츄 › 일상컷 · 6/12`. 공방·화풍·대상·출력 칩 넷은 여기로 들어가고(누르면 그 단계), 칩 레일에서는 뺀다. `6/12` 는 단계 번호 — 칩 레일과 같은 차례.
- 레일은 `position: sticky; top: 0` — 판이 아무리 길어도 경로와 칩은 보인다. 높이는 두 줄 ≈ 96px 안.

### ② 칩 레일 — 줄바꿈 대신 가로 스크롤 한 줄
- `.hchips` 를 폭 ≤ 768 에서 `flex-wrap: nowrap; overflow-x: auto; scroll-snap-type: x proximity; scrollbar-width: none` — 한 줄.
- 다시 그릴 때 `.hchip.on` 을 `scrollIntoView({ inline: 'center', block: 'nearest' })` — 지금 칸이 늘 가운데.
- 칩 글은 **한국어 머리만**: `label()` 이 돌려주는 「over shoulder — 뒤돌아보기」는 「—」 뒤만, 「calm — 차분함」도 뒤만. 칩 최대 폭 160px · `text-overflow: ellipsis`. 값이 비었으면(아직 안 온 단계) 「▸」 만 — 다음 칸이 무엇인지 보이게 **다음 한 칸은 미리 띄운다**(지금은 안 띄운다).
- 「다 골랐다」 상태에서 레일은 그대로(전부 한 줄 스크롤) — 지금처럼 9줄이 되지 않는다.

### ③ 아래 막대 — 단추를 엄지 자리로
- `.bar`(해방·랜덤·다음·다 골랐다로)를 판 밑이 아니라 **`position: sticky; bottom: 0`** 막대로. 안전 영역(`env(safe-area-inset-bottom)`) 더함. 판 끝에 막대 높이만큼 여백.
- 칸 넷: 「‹ 이전」(앞 단계로 — 지금은 칩으로만 돌아간다) · 「🔓 해방 (n)」(토글, n 은 트리 밖 개수) · 「🎲 랜덤 ▾」(누르면 두 줄 메뉴: 이 칸 랜덤 · 여기부터 다 랜덤 · (있으면) 다 골랐다로) · 「다음 ›」(단계에 `next` 가 있을 때. 고르기 단계는 고르는 순간 넘어가니 「건너뛰기」).
- 글 칸(덧붙임·외형 직접 입력)에 초점이 가면 막대는 숨긴다(`focusin`/`focusout`) — 키보드와 겹치지 않게.
- 「다 골랐다」에선 막대가 **결과 막대**(📋 복사 · 기록 JSON · 🎲 처음부터)로 바뀐다.

### ④ 선택지 — 1열 줄, 묶음은 탭
- 폭 ≤ 768: `.opts` 1열, 칸은 44~52px 한 줄(`<b>` 제목 왼쪽, `<span>` 꼬리는 오른쪽 흐리게 한 줄 `ellipsis`). 지금의 2열·두 줄 설명 카드는 PC 용으로 남긴다.
- 꼬리 글이 영어 설명이면(`sub`) 줄 끝에 한 줄로 자르고, 누르고 있으면(`title`) 다 보인다. 하는 일의 `tag`(묶음 이름)는 오른쪽 작은 글.
- **묶음 탭**: `optButtons` 가 묶음(`group`)을 만들 때 묶음이 둘 이상이면 판 위에 가로 스크롤 탭(전체 · 집 · 거리·도시 · …)을 두고 한 묶음만 보인다. 탭 상태는 `st.tab[단계]`. 장소 4,900px → 한 묶음 ≈ 600px.
- 고른 칸은 왼쪽 ● 표시 + 금빛 테두리(지금 색 그대로). 누르면 `aria-pressed`.

### ⑤ 해방 — 같은 목록 안에 흐리게
- 켜면 트리 밖 선택지를 **본 목록에 끼운다**(묶음 안 제자리, 흐리게 + 🔓 + 까닭 한 줄) — 따로 아래 목록을 두지 않는다. 묶음 탭의 수에도 포함(`집 · 3+2`).
- 아래 막대의 해방 토글은 켜진 동안 금빛, 숫자는 트리 밖 개수.

### ⑥ 대상 — 건너뛰기와 최근
- 찾기 칸 아래 **건너뛰기 칩 한 줄**: 포켓몬은 세대(1~9, `card.gen`), 게임·책·신화 무기는 가나다 첫 글자(ㄱ·ㄴ·ㄷ…·A). 누르면 그 자리로 `scrollIntoView`.
- 맨 위 **최근 고른 대상**(저장값 `by[a].recent`, 다섯까지) 한 줄 — 같은 인물을 다시 고르는 일이 잦다.
- 1,025명은 다 그리되(스크롤 막힘 때문에 안에 상자를 안 둔 결정은 유지) `content-visibility: auto; contain-intrinsic-size: 0 52px` 로 칸마다 그리기를 미룬다 — 36,000px 쪽이 가볍다.
- 끝에서 고르면 `render()` 가 레일 아래(`panel` 윗머리)로 올린다 — 지금은 「윗머리가 화면 위일 때만」인데 늘 올린다(③ 과 같이 `scrollIntoView({ block: 'start' })` + 레일 높이만큼 `scroll-margin-top`).

### ⑦ 결과 — 위로, 그리고 복사는 늘 손 닿는 데
- 「다 골랐다」 판 **첫 칸이 지시문**: `#out` 를 `#panel` 안 맨 위로 옮긴다(또는 done 일 때 panel 다음이 아니라 panel 안에 그린다). 글 칸은 8줄(≈190px)까지, 「펼치기」로 전체.
- 아래 막대 = 결과 막대(📋 복사 · 기록 JSON · 🎲 처음부터). 복사하면 막대 글이 「복사했다 ✓」 로 1.5초.
- 단계 중에도 지시문이 있으면(카드 갈래는 처음부터 있다) 막대 왼쪽 끝에 **「지시문 437낱말」 작은 단추** — 누르면 결과 시트가 아래에서 올라온다(`<dialog>` 또는 panel 위에 덮는 판). 고치다가 바로 확인·복사.

### ⑧ 자잘한 것
- 단계가 바뀌면 늘 새 단계 윗머리를 레일 바로 아래로(⑥ 과 같은 셈). 뒤로 돌아갈 땐 그 단계의 고른 칸이 보이게 `scrollIntoView({ block: 'center' })`.
- `select`(세부 강도·연출·외형) 는 폰에서 OS 고르개가 뜨니 그대로 두되, 라벨과 고르개를 한 줄에(라벨 40% · 고르개 60%) — 지금은 두 줄.
- 외형 묶음 `<details>` 는 한 번에 하나만 열린다(다른 것을 열면 앞 것 닫힘) — 긴 쪽을 막는다. 열린 상태는 지금처럼 기억.
- 덧붙임 글 칸은 `rows="2"`, 초점이 오면 자라게(`field-sizing: content` 되는 브라우저는 그걸로).
- 동작 줄이기(`prefers-reduced-motion`)면 레일 가운데 맞춤·시트 올라오기 없이 바로.

## 4. 차례 — 효과 큰 것부터

1. ②③ 칩 레일 한 줄 + 아래 막대 (가장 큰 체감 — 판이 화면 안에 들어오고 단추가 손에 온다). CSS 가 대부분, JS 는 `render()` 의 가운데 맞춤·막대 그리기.
2. ④⑤ 선택지 1열 + 묶음 탭 + 해방 끼워 넣기 (`optButtons` 하나 고치면 모든 단계에 적용).
3. ⑦ 결과 위로 + 결과 막대 + 지시문 시트.
4. ① 머리 줄이기 + 경로 한 줄.
5. ⑥ 대상 건너뛰기·최근.
6. ⑧.

하나 끝날 때마다 `tests/prompt-screen.cjs` ③(344·390·1280 넘침·44px)에 더한다: 레일이 한 줄인가(`scrollWidth > clientWidth` 이고 높이 ≤ 60) · 아래 막대가 화면 안(`bottom ≤ innerHeight`)인가 · 장소 단계 쪽 높이가 1,500px 아래인가 · 「다 골랐다」에서 지시문 윗머리가 첫 화면(≤ 844) 안인가 · 대상 끝에서 고른 뒤 새 단계 윗머리가 레일 아래인가.
지시문 글은 하나도 안 바뀐다 — `tests/prompt-parity.cjs` 가 그대로 지켜 준다.

## 5. 안 바꾸는 것
- 단계의 차례·트리·해방·랜덤·계획기 규칙, 저장 꼴, 지시문. 옛 공방 생성기.
- PC 배치(폭 > 768). 칩 줄바꿈·2열 카드·판 밑 단추는 PC 에선 그대로.
